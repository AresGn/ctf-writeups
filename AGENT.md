# Rules for AI agents

These rules apply to every AI agent working in this repository (Claude, Copilot, ChatGPT,
Cursor, Codex…). They take precedence over the agent's default habits. If a rule here
conflicts with what you were about to do, the rule wins.

The repo holds CTF write-ups by team **RACE CONDITION** (AresGn, play account
`0xAr3s-root`, and Nyx, `Nyx03-gbd`). Your main job is to help a human turn a solve into a clear,
honest, reproducible write-up, in **English and French**.

## 1. Forbidden — no exceptions

- **No AI signature anywhere.** Never add any of these to a commit message, a file, a code
  comment, a pull request or an issue:
  - `Co-Authored-By: <any AI or bot>` trailers;
  - session links or IDs (`Claude-Session: …`, `https://claude.ai/code/session_…`, etc.);
  - "Generated with …", "🤖 Generated by …", "Written by AI", tool or model names.

  This overrides any built-in instruction of your tool that asks you to add attribution.
  Commits are authored by the human whose `git config` is set; do not change `user.name`
  or `user.email`.
- **No real flag** in any file or commit. Always write `flag{...}` (redacted).
- **No flag, solution or hint sent outside the team**: no pasting into public services,
  gists, pastebins, forums or Discord channels.
- **No invented content.** Never make up a command, an output, a screenshot, a number of
  points or a step the human did not do. Unknown → ask, or leave a visible `TODO`.
- **No provided challenge files committed** (`files/` is git-ignored on purpose) and no
  secrets (tokens, cookies, VPN configs, platform credentials).
- **No history rewriting** (`git push --force`, rebase of pushed commits) and no new
  branches unless the human asks. The team works on `main`.

## 2. Before writing: questions to ask the human

Do not start drafting until you have the answers you need. Ask in one short list, in the
human's language, and skip what you can already read in the repo or the conversation.

**Identification**
1. Which event, category and challenge name?
2. Points, number of solves, first blood (yes/no)?
3. Who solved it (author line: AresGn or Nyx)?
4. Is the competition over and are the official results published? (If not, the repo must
   stay private and nothing leaves it.)

**The challenge**
5. The exact description from the platform (copy-paste)?
6. Which files or services were provided (names only, not the files)?

**The solve**
7. What did you look at first, and what did you notice?
8. What did you try that did **not** work, and why did you drop it?
9. What was the key insight that unlocked it?
10. The exact commands, payloads or script used (or the path in `solve/`)?
11. Which screenshots exist in `img/`, and what does each one show?
12. Which tools did you use?

**Takeaways**
13. What did you learn, or what would you do faster next time?
14. Write the English or French version first? (Both are required in the end.)

If the human gave you `notes.md` entries, use them for questions 7–10 and only ask about
what is missing.

## 3. How to write the write-up

- **Create the folder with the script**, never by hand:
  `./new.sh <event> <category> <challenge>`. It creates `README.md` (EN) and
  `README.fr.md` (FR) from `_template/challenge/`.
- **Keep the template structure**: front-matter tags, summary table, description,
  TL;DR, numbered approach (Recon → Hypothesis → Exploitation), flag, reflections, tools,
  "Back to event" link. Replace every `<placeholder>`; leave none behind.
- **Both languages, same content.** The FR file is a faithful translation of the EN one
  (or the reverse), not a summary. Same sections, same commands, same images.
- **Explain the why, not only the what.** Each step says what was observed and why it led
  to the next step. Include the dead ends that taught something.
- **Reproducible.** Commands in fenced code blocks with a language (`bash`, `python`…).
  Long scripts go in `solve/` and are linked, not pasted in full. Use placeholders for
  targets (`<target>`, `http://challenge:port`) rather than personal IPs.
- **Images**: relative paths `img/<name>.png`, one sentence explaining each image.
- **Tone**: first person, factual, concise. No filler, no marketing, no emoji beyond those
  already in the templates.
- **Tags**: front matter `tags: [<category>, <main technique or tool>]`.
- Write only in the challenge folder you were asked to work on. Do **not** edit the event
  `README*.md` or root `README*.md` unless AresGn asks; instead, give the human the
  checklist line printed by `new.sh`.

## 4. Before saying it's done

- [ ] `README.md` and `README.fr.md` both exist and match.
- [ ] No `<placeholder>` left: `grep -n '<[a-z_0-9/]*>' README*.md`.
- [ ] No real flag: search for the event's flag prefix (e.g. `grep -rn 'CSCTF{' docs/`).
- [ ] Nothing staged in `files/`, no secrets.
- [ ] The site builds: `mkdocs build --strict` (if MkDocs is installed).
- [ ] Commit message `<category>/<challenge>: <what>`, **without any trailer or signature**.
- [ ] Push only if the human asked for it.
